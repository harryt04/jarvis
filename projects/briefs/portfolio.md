## Purpose and current shape

This is more than a static résumé: a Next.js App Router public identity site, curated project discovery surface, and shared user/CRM write endpoint. The README calls it “Wiki + resume” (`README.md:1–13`), but inspected routes provide `/`, `/work`, sitemap, and `/api/user`; no wiki interface is present. Public visitors browse projects; external product integrations can submit user/app associations. No CRM dashboard, login, email delivery, or offline portfolio implementation was found. The résumé is a linked static PDF; its contents were deliberately not inspected.

The manifest declares Next 16, React 18, TypeScript, Tailwind, Radix primitives, MongoDB and PostHog (`package.json:14–45`). Route shells own navigation/metadata, `lib/portfolio-projects.ts` owns curated content, the client showcase owns iframe state, providers own theme/analytics, and Mongo helpers plus the route own persistence. Unused visual components do not establish an active skills cloud or other product feature.

## Three source-traced flows

**1. Visitor to project.** `/` renders a local portrait and four links; internal work/PDF links remain in-tab, while external profile links use a new tab and `noreferrer` (`app/page.tsx:16–36,38–98`). `/work` imports the typed ten-project array and passes it into `ProjectShowcase`, preserving app/source links independently of preview availability (`app/work/page.tsx:6–15,94–96`; `lib/portfolio-projects.ts:1–92`; `components/custom/projectShowcase.tsx:140–193`). There is no GitHub fetch or database dependency in this content flow. Canonicals and sitemap cover home, work, and PDF (`app/sitemap.ts:3–10`).

**2. Card to live preview.** Each card starts with a placeholder. An IntersectionObserver with 400px margin permanently marks it eligible; enabled eligible cards mount an iframe with `embed=portfolio`, native lazy loading, script/same-origin sandbox permissions, and a conservative referrer policy. Loading sets a nine-second fallback timer; `onLoad` replaces loading/fallback with a “Live” label (`components/custom/projectShowcase.tsx:10–96`). CSS disables pointer interaction and reserves 16:10 space (`app/globals.css:122–129`). These are embedded external pages, not local `/preview` routes. A load event cannot establish child application health, and the query marker only enables downstream traffic attribution—it does not prove child analytics exclude previews.

**3. Product registration to CRM.** POST parses JSON, requires only truthy `email`, filters array-valued `usesApps` against the allowlist, and looks up the exact email in Mongo. Existing records only merge/deduplicate/sort app membership; identical membership or no valid app array returns `operation: none`. Supplied names, status, source, and notes are ignored for existing records. New records receive those optional fields, default status `emailOnly`, and a Denver-localized joined string via `$setOnInsert`; upsert returns 201/created with ID or 200/updated (`app/api/user/route.ts:5–155`). Creation or changed membership awaits a Discord webhook notification containing email/app membership; missing configuration skips it, network rejection is logged, and HTTP error statuses are not checked (`:157–176`). No notification was sent during review.

## Data and trust boundaries

`models/users.ts:1–22` allows `voicebridge`, `tokei`, `sky-survey`, and `pantryiq`; these are supported identifiers, not verified active consumers. No local UI caller of `/api/user` was found. External consumer request shape, retry policy, origin configuration, and deployment protections require separate evidence outside this read-only source scope. The ten showcase projects and four CRM identifiers are distinct lists.

The TypeScript user type includes customer/contact statuses and marketing consent, but the route does not validate email syntax/types, normalize addresses, enforce status enums, or persist `allowsMarketingEmails`. No route-level authentication, authorization, rate limiting, or origin/CORS handling appears. Object-valued input and malformed JSON are consequential validation gaps; thrown errors return 500 with `error.message` (`route.ts:8–55`). Do not infer a consent workflow from the model.

Mongo uses a module-scoped client/promise and selects `harry-dev-llc-email-list-${NODE_ENV}.users`; missing connection configuration throws at import, and a rejected connection promise has no reset path (`lib/mongo-client.ts:1–31`). Index creation is separate: `gulpfile.ts:1–7` calls `lib/mongo-utils.ts:6–34`, including unique email plus search/status indexes. Deployment index existence is unverified. Lookup then upsert is nontransactional; concurrent app merges can overwrite membership, while uniqueness depends on the separately provisioned index. Joined is a display-oriented string, not consistently a BSON date.

## Analytics, theme, delivery, and conflicts

The root wraps both pages in PostHog and next-themes. Theme defaults to system, persists under `harryt-portfolio-theme`, and offers light/dark/system (`app/layout.tsx:30–40`; `components/custom/themeSwitcher.tsx:15–45`). Reduced-motion CSS removes hover transforms (`app/globals.css:156–169`). Browser PostHog requires its public key even outside production, initializes only in production/browser, samples web-vitals at 50%, and explicitly captures pathname pageviews (`providers/posthogProvider.tsx:8–35`). The server client helper has no discovered caller. `next.config.js:7–24` supplies `/ingest` rewrites, but an empty `next.config.mjs` also exists; effective config selection remains unverified.

The approved design document records a restrained two-page showcase, curated metadata, and no résumé expansion (`docs/portfolio-showcase-plan.md:5–50`). It requires tap-to-load, at most one mobile iframe, and initially disabled Platter/Blockparty previews (`:224–252`). Current code has no mobile branch/unmount coordination and enables all ten; historical TLS observations are not evidence of current outages. Preserve this discrepancy for review rather than silently treating implementation as revised policy.

That script checks Prettier, ESLint, then builds with dummy analytics/database configuration; it does not exercise CRM storage or iframe health (`package.json:5–12`).
