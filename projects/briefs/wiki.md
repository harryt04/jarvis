## Discovery → spaces → navigation

`listMarkdownFiles` recursively visits directories, accepts regular files ending in lowercase `.md`, and sorts paths. React `cache` wraps index construction. Each file is read and parsed by gray-matter; title falls back to the first H1 then normalized filename, description to the first non-heading nonempty cleaned line, truncated to 160 characters. Category is explicit frontmatter, otherwise the first folder below the space, or `Overview` at its root. Numeric order is checked; other frontmatter mostly receives TypeScript assertions rather than runtime schema validation. `draft` uses Boolean coercion, so a quoted string `"false"` is truthy. [lib/content.ts:61–262](https://github.com/harryt04/wiki/blob/f0531a3748f2378537975bce04a2f96a3bd8353b/lib/content.ts#L61-L262).

Paths become lowercase slugs; terminal README disappears. Thus a hypothetical `content/example/guides/Setup.md` becomes `/example/guides/setup`, and the space README becomes `/example`. Records are keyed both by route and exact source-relative path. Case-folding collisions and README-versus-same-name-file collisions are not rejected: map assignment can overwrite a route while the document list retains both entries.

Space metadata comes from raw records; navigation comes from filtered documents. Navigation excludes the home route, honors configured group order, appends unlisted categories alphabetically, then sorts documents by numeric order and title. Breadcrumbs link only to indexed documents. `/` calls `getSpaces()` and renders title, description, count, and link cards. [lib/content.ts:357–438](https://github.com/harryt04/wiki/blob/f0531a3748f2378537975bce04a2f96a3bd8353b/lib/content.ts#L357-L438), [components/space-index.tsx:24–34](https://github.com/harryt04/wiki/blob/f0531a3748f2378537975bce04a2f96a3bd8353b/components/space-index.tsx#L24-L34).

Important code/document mismatch: policy requires a root `content/<space>/README.md`, but `isSpaceHome` tests basename only and the lookup accepts the first README anywhere within that space. A nested README can satisfy validation and supply the wrong metadata; entirely empty folders are invisible because space IDs derive from discovered markdown. The claimed build check therefore has narrower coverage than the docs imply.

## Route → rewritten links → article

The catch-all awaits params, fetches by indexed href, and returns 404 for missing documents. Lookup rejects empty segments, `..`, and embedded `/`; it resolves records rather than opening arbitrary request paths. Metadata uses the same index. Rendering rereads the indexed file and runs remark parse → GFM → custom link rewrite → remark-rehype → heading slugs/autolinks → stringify. HTML enters the article through `dangerouslySetInnerHTML`. [app/[...slug]/page.tsx:9–26](https://github.com/harryt04/wiki/blob/f0531a3748f2378537975bce04a2f96a3bd8353b/app/%5B...slug%5D/page.tsx#L9-L26), [lib/content.ts:264–355](https://github.com/harryt04/wiki/blob/f0531a3748f2378537975bce04a2f96a3bd8353b/lib/content.ts#L264-L355), [components/document-page.tsx:14–64](https://github.com/harryt04/wiki/blob/f0531a3748f2378537975bce04a2f96a3bd8353b/components/document-page.tsx#L14-L64).

Rewriting visits direct link nodes, skips URL/protocol-relative and fragment-only links, resolves `.md` paths relative to the current source, and rewrites only indexed targets, retaining the fragment. Missing targets remain unchanged without build failure. Reference links, images, uppercase `.MD`, and query-bearing `.md?…` targets are outside this rewrite. Source-path lookup remains case-sensitive despite lowercase route generation. This is route adaptation, not a link checker or asset copier.

The trust boundary is repository publication: no application authorization separates spaces. “Trusted local markdown” is an ownership assumption, not proof of safe arbitrary uploads. The pipeline has no explicit sanitizer or raw-HTML plugin; do not extend it to untrusted authors without reviewing URL, HTML, and heading-ID handling. External content URLs can still send readers or image requests elsewhere. Nothing here establishes private hosting, access controls, or offline guarantees.

## Drafts, build, and delivery

Production filters drafts before route, navigation, metadata, link-target, and sitemap consumption; development includes them. Space discovery still uses raw documents, so draft-home titles/descriptions can appear on public index cards, including a card whose home returns 404. Drafts are not confidentiality controls. References to excluded drafts remain unresolved markdown URLs.

`generateStaticParams` and sitemap both consume `getAllRouteParams`; sitemap additionally includes `/` and hardcodes `https://wiki.harryt.dev`. Configuration preserves four legacy route families with permanent redirects. This is a Next server with prerendered routes, not configured static export.
