## Purpose and current state

This is a reusable document kit for a SaaS project lead and an LLM orchestrator: clarify a business concept, specify an MVP, decompose implementation, and write dispatchable agent prompts. The tracked inventory is four Markdown templates plus `.gitignore`; there is no README, application, package manifest, CI workflow, task runner, or installed orchestration integration. Consequently, “Ready for Implementation” and “Ready for orchestration” are template defaults, not evidence of approved requirements or working software ([PRD-TEMPLATE.md:1–10](https://github.com/harryt04/prompts/blob/2948559685a99f0be5ef760280d1d2d2f100ade6/PRD-TEMPLATE.md#L1-L10), [ORCHESTRATION-TEMPLATE.md:1–7](https://github.com/harryt04/prompts/blob/2948559685a99f0be5ef760280d1d2d2f100ade6/ORCHESTRATION-TEMPLATE.md#L1-L7)).

## The reusable flow

**Concept → product contract.** `app-outline-template.md` starts with names, vision, mission, funding, compensation, and decision authority, then separates MVP features from a feedback-dependent wishlist. It also prompts architecture justification, alternative pricing models, communication, and project management. A lead can use this as discovery input to the PRD’s problem, personas, feature requirements, architecture, scope exclusions, and success metrics. That first handoff is inferred from complementary content; no script or explicit outline-to-PRD conversion exists ([app-outline-template.md:8–66](https://github.com/harryt04/prompts/blob/2948559685a99f0be5ef760280d1d2d2f100ade6/app-outline-template.md#L8-L66); [PRD-TEMPLATE.md:14–120](https://github.com/harryt04/prompts/blob/2948559685a99f0be5ef760280d1d2d2f100ade6/PRD-TEMPLATE.md#L14-L120)).

**Product contract → implementation units.** The PRD captures service ownership, routes, infrastructure, scaling triggers, data shape, nonfunctional targets, integrations, operations, and decision rationale. The TRD explicitly translates `.agents/spec/PRD-FINAL.md` into parallelizable units with files, dependencies, acceptance criteria, and tests. It expands technology choices and schema into layered work, environment contracts, test strategy, and migration preservation notes. Ownership is documentary: the lead must fill and reconcile these artifacts; nothing automatically validates the translation ([PRD-TEMPLATE.md:154–258](https://github.com/harryt04/prompts/blob/2948559685a99f0be5ef760280d1d2d2f100ade6/PRD-TEMPLATE.md#L154-L258); [TRD-TEMPLATE.md:3–16](https://github.com/harryt04/prompts/blob/2948559685a99f0be5ef760280d1d2d2f100ade6/TRD-TEMPLATE.md#L3-L16), [83–115](https://github.com/harryt04/prompts/blob/2948559685a99f0be5ef760280d1d2d2f100ade6/TRD-TEMPLATE.md#L83-L115)).

**Implementation units → dispatch and reconciliation.** The orchestration guide tells leads to copy it to `.agents/ORCHESTRATION.md`, fill metadata, enumerate phases, replace placeholders, and make dependencies accurate. Each prompt packages role, objective, measurable acceptance, file edits, optional dependency/environment needs, tests, and notes. The intended orchestrator reads prerequisites, dispatches concurrent OpenCode `task()` calls within a layer, waits at the barrier, and updates checkboxes. Missing prerequisites halt execution; failed units surface to a human, who chooses retry/skip and approves proceeding. This is a written operating procedure, with manual status reconciliation, rather than executable scheduling or verified tool compatibility ([ORCHESTRATION-TEMPLATE.md:23–52](https://github.com/harryt04/prompts/blob/2948559685a99f0be5ef760280d1d2d2f100ade6/ORCHESTRATION-TEMPLATE.md#L23-L52), [227–253](https://github.com/harryt04/prompts/blob/2948559685a99f0be5ef760280d1d2d2f100ade6/ORCHESTRATION-TEMPLATE.md#L227-L253)).

## Decisions, boundaries, and gotchas

The durable repository-level choices are explicit dependencies, self-contained work units, measurable acceptance, unit/E2E coverage, environment assumptions, and human handling of failures. These are project-scoped template conventions attributable to this snapshot, not proof of Harry’s universal policy. PostgreSQL v18, Zero, Redis, Next.js, Fly.io, Fastify, and pricing options are examples or placeholders; no stack, vendor, funding model, price, or deployment is actually selected. Even the TRD’s literal `mvp` branch is a scaffold assumption; the source checkout is `master` ([PRD-TEMPLATE.md:7–9](https://github.com/harryt04/prompts/blob/2948559685a99f0be5ef760280d1d2d2f100ade6/PRD-TEMPLATE.md#L7-L9); [ORCHESTRATION-TEMPLATE.md:277–302](https://github.com/harryt04/prompts/blob/2948559685a99f0be5ef760280d1d2d2f100ade6/ORCHESTRATION-TEMPLATE.md#L277-L302)).

Parallelism examples need correction before reuse: orchestration WU-0.2 depends on WU-0.1 despite both being Layer 0 under “All Parallel.” The TRD similarly gives WU-1.2 a WU-1.1 dependency, while its schedule says both can parallelize “if interface agreed.” Neither supplies a mechanism for resolving shared-file edits, lockfiles, merge conflicts, rollback, cancellation, or proving completion beyond checkboxes. The stated independence rule should trigger review of every dependency edge ([ORCHESTRATION-TEMPLATE.md:147–154](https://github.com/harryt04/prompts/blob/2948559685a99f0be5ef760280d1d2d2f100ade6/ORCHESTRATION-TEMPLATE.md#L147-L154); [TRD-TEMPLATE.md:237–264](https://github.com/harryt04/prompts/blob/2948559685a99f0be5ef760280d1d2d2f100ade6/TRD-TEMPLATE.md#L237-L264)).

Auth, account scope, sessions, permissions/RLS, retention, backups, API authentication, and rate limits are questions to resolve in a consuming project, not implemented protections. Sync is contemplated but offline behavior and reconciliation guarantees remain unspecified. Environment blocks contain placeholders, not credentials. `.agents/spec/PRD-FINAL.md`, `.agents/SETUP-CHECKLIST.md`, `.env.sample`, and the project README are absent here. The hypothetical BlogEngine example dated 2026-04-15 is illustrative text already present in the April 10 commit, not a later deployment record ([PRD-TEMPLATE.md:240–281](https://github.com/harryt04/prompts/blob/2948559685a99f0be5ef760280d1d2d2f100ade6/PRD-TEMPLATE.md#L240-L281); [ORCHESTRATION-TEMPLATE.md:306–337](https://github.com/harryt04/prompts/blob/2948559685a99f0be5ef760280d1d2d2f100ade6/ORCHESTRATION-TEMPLATE.md#L306-L337)).
