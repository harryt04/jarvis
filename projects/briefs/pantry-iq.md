**Architecture and tenant path.** This is a strict TypeScript Next.js 15/React 19 monolith: `app/` handles pages and thin request adapters; `components/` handles interaction; `src/server/` owns domain services. PostgreSQL/Drizzle holds identity, canonical operational records, audit history, metric runs/results/rollups, reconciliation, and job state. `csv` owns upload/preview/mapping/import orchestration; `ingestion` supplies source-independent normalization/persistence; `metrics` composes inventory, `menu`, and `staffing` calculations; `chat` narrates; `connectors` adapts vendors; `storage` isolates S3 access. Server-rendered pages call services directly, while interactive forms use route handlers. [Stack contract, `docs/tech-stack.md:45`](https://github.com/harryt04/pantry-iq/blob/63c7ebfeee4f4fe68a139beba9ba44568f05c8eb/docs/tech-stack.md#L45), [precompute composition](https://github.com/harryt04/pantry-iq/blob/63c7ebfeee4f4fe68a139beba9ba44568f05c8eb/src/server/metrics/precompute.ts#L22).

Better Auth owns local user/session/account/verification tables, password reset, and verification delivery; passwords require 12 characters, and reset revokes sessions. Creating a location takes the session’s user ID, not an owner supplied by the browser. App-shell rendering redirects anonymous users and lists only active owned locations. `requireOwnedLocation` validates UUIDs and queries both location ID and session user ID. Internal loaders accepting a bare location ID rely on callers preserving that boundary. There are no organization/role or recipient account models. Real-database ownership tests stub authentication but exercise the ownership predicate. **CSV → canonical records.** The wizard progresses through upload, mapping, exact item matching, and confirmation. It persists unfinished jobs—including previews, mappings, and resolutions—in browser localStorage by location; resumption re-fetches the owned upload, so this is convenience state, not offline ingestion. Upload authorization precedes storage. Generated UUID keys avoid user filenames; a streaming content guard rejects binary/control-byte content and enforces **10 MB**. A process-local limiter defaults to ten uploads per account/location/hour. S3 upload precedes inserting `uploaded` history; failures attempt object deletion. [Wizard persistence](https://github.com/harryt04/pantry-iq/blob/63c7ebfeee4f4fe68a139beba9ba44568f05c8eb/components/import/csv-upload-form.tsx#L155), [upload boundary](https://github.com/harryt04/pantry-iq/blob/63c7ebfeee4f4fe68a139beba9ba44568f05c8eb/src/server/csv/uploads.ts#L56), [guard and export formula defense](https://github.com/harryt04/pantry-iq/blob/63c7ebfeee4f4fe68a139beba9ba44568f05c8eb/src/server/csv/security.ts#L119).

Preview detects encoding/delimiter/header problems and reuses mappings from the same location/type. Item resolution permits deterministic presentation normalization and known modifier stripping, then requires full canonical-name equality; misses require explicit link/create choices. Commit re-reads the owned object and mapping, rejects unresolved items, and transactionally creates items, persists normalized sales/purchases/counts/labor, updates usage/history, and enqueues precompute. Repeating an imported upload returns `alreadyImported`; sales/labor use conflict-ignore persistence backed by location/source/external-ID uniqueness. Purchases check identity first; inventory deduplicates timestamp/item/quantity/source in application memory. Do not assume all record types have equally strong concurrent idempotency. [Exact matching](https://github.com/harryt04/pantry-iq/blob/63c7ebfeee4f4fe68a139beba9ba44568f05c8eb/src/server/ingestion/item-resolution.ts#L26), [commit transaction](https://github.com/harryt04/pantry-iq/blob/63c7ebfeee4f4fe68a139beba9ba44568f05c8eb/src/server/csv/imports.ts#L251), [finalization/enqueue](https://github.com/harryt04/pantry-iq/blob/63c7ebfeee4f4fe68a139beba9ba44568f05c8eb/src/server/csv/imports.ts#L373), [persistence variants](https://github.com/harryt04/pantry-iq/blob/63c7ebfeee4f4fe68a139beba9ba44568f05c8eb/src/server/ingestion/persistence.ts#L85).

**Metrics → recommendations → explanation.** Monetary/quantity columns are PostgreSQL `numeric`. Metric functions accept decimal strings, implement scaled BigInt arithmetic, and return either calculated values with inputs/units/rounding or explicit `cannot-calculate` reasons. `businessDayBucket` uses the location timezone and configurable boundary (default 04:00), assigning earlier local times to the preceding service date. Dashboard readiness defaults to seven distinct business days; prediction eligibility requires four weeks, and demand forecasting requires 28 distinct business days. Ranking defaults to impact 0.40, urgency 0.40, sufficiency 0.20, capped at five. Recommendations preserve observed facts, financial basis, optional prediction basis, “consider” actions, missing-data findings, and evidence references. [Exact arithmetic](https://github.com/harryt04/pantry-iq/blob/63c7ebfeee4f4fe68a139beba9ba44568f05c8eb/src/server/metrics/definitions.ts#L1), [business days](https://github.com/harryt04/pantry-iq/blob/63c7ebfeee4f4fe68a139beba9ba44568f05c8eb/src/server/metrics/definitions.ts#L644), [runtime defaults](https://github.com/harryt04/pantry-iq/blob/63c7ebfeee4f4fe68a139beba9ba44568f05c8eb/src/server/metrics/config.ts#L37), [recommendation shape](https://github.com/harryt04/pantry-iq/blob/63c7ebfeee4f4fe68a139beba9ba44568f05c8eb/src/server/metrics/recommendations.ts#L107).

Precompute detects cross-source conflicts and excludes unresolved or nonauthoritative overlapping records. It loads/calculates before a transaction that atomically appends run/results/rollups and marks success; readers select the latest successful run. pg-boss schedules daily fan-out at **04:00 UTC**, with retries, per-location FIFO/singleton controls, and transactional Drizzle enqueue for CSV/item edits. This schedule is distinct from each restaurant’s business boundary. Reconciliation instead commits its decision then swallows enqueue errors; connector sync commits pages/cursors and enqueues after completion. These paths have weaker invalidation guarantees. [Filtering](https://github.com/harryt04/pantry-iq/blob/63c7ebfeee4f4fe68a139beba9ba44568f05c8eb/src/server/metrics/precompute.ts#L1039), [atomic result publication](https://github.com/harryt04/pantry-iq/blob/63c7ebfeee4f4fe68a139beba9ba44568f05c8eb/src/server/metrics/precompute.ts#L1368), [scheduler](https://github.com/harryt04/pantry-iq/blob/63c7ebfeee4f4fe68a139beba9ba44568f05c8eb/src/server/metrics/scheduler.ts#L149), [reconciliation enqueue](https://github.com/harryt04/pantry-iq/blob/63c7ebfeee4f4fe68a139beba9ba44568f05c8eb/app/api/reconciliation/route.ts#L39), [connector page commits](https://github.com/harryt04/pantry-iq/blob/63c7ebfeee4f4fe68a139beba9ba44568f05c8eb/src/server/connectors/framework.ts#L294).
