## Purpose and authority

KanjiForge is an offline-first Japanese study PWA whose defining model is visible five-level, belt-colored progress. It targets independent learners on iOS Safari, Android, and desktop. Study requires an account; an already verified identity permits offline continuation. Owning recoverable study data and grading without network dependence are stronger architectural commitments than any particular sync transport. ## Grade → local transaction → reconciliation

`features/study/store.ts` owns the Zustand session queue. `deck-loader.ts` combines immutable content references with user progress; derived decks obtain membership from the shipped catalog, while Saved/custom decks persist membership. An absent card state means an untouched card, rather than missing initialization work. Pure `core/srs` owns transitions, scheduling, queue construction, and replay; repository adapters translate `stickyId` to `contentRef`. [deck-loader.ts:40–82](https://github.com/harryt04/kanji-forge/blob/c6c90e354db9cb4605cf7d46a95eccf57d261adf/src/features/study/deck-loader.ts#L40-L82), [core/README.md:14–33](https://github.com/harryt04/kanji-forge/blob/c6c90e354db9cb4605cf7d46a95eccf57d261adf/src/core/README.md#L14-L33)

`good` advances one level, `easy` jumps to four, and `again` demotes, with the required gentler one-level demotion when fewer than ten red cards exist. Grading and scheduling are separate functions. The store awaits `recordGrade()` before advancing the queue: that repository method atomically inserts the review, writes its materialized state, increments daily statistics, and inserts an outbox row whose ID must equal the review ID. Network flushing is outside this transaction. Undo appends a compensating manual review rather than deleting the original. [grade.ts:24–49](https://github.com/harryt04/kanji-forge/blob/c6c90e354db9cb4605cf7d46a95eccf57d261adf/src/core/srs/grade.ts#L24-L49), [store.ts:156–217](https://github.com/harryt04/kanji-forge/blob/c6c90e354db9cb4605cf7d46a95eccf57d261adf/src/features/study/store.ts#L156-L217), [repo/index.ts:722–749](https://github.com/harryt04/kanji-forge/blob/c6c90e354db9cb4605cf7d46a95eccf57d261adf/src/data/repo/index.ts#L722-L749), [store.ts:277–318](https://github.com/harryt04/kanji-forge/blob/c6c90e354db9cb4605cf7d46a95eccf57d261adf/src/features/study/store.ts#L277-L318)

The actual local engine is `sql.js`, not PGlite: each authenticated user gets a SQLite namespace and OPFS snapshot. A promise chain serializes writes; SQLite commits precede exporting the whole database to OPFS. Storage unavailability/read/write errors are swallowed to preserve session-local study, so a successful grade does not establish durable persistence. Browser eviction protection is requested after a completed nonempty session. [db/index.ts:54–101](https://github.com/harryt04/kanji-forge/blob/c6c90e354db9cb4605cf7d46a95eccf57d261adf/src/data/db/index.ts#L54-L101), [db/index.ts:168–195](https://github.com/harryt04/kanji-forge/blob/c6c90e354db9cb4605cf7d46a95eccf57d261adf/src/data/db/index.ts#L168-L195), [storage-persistence.ts:42–58](https://github.com/harryt04/kanji-forge/blob/c6c90e354db9cb4605cf7d46a95eccf57d261adf/src/pwa/storage-persistence.ts#L42-L58)

## Server ownership and consequential gaps

The Next.js application serves UI and API together. Lazy `getServerContext()` is load-bearing: route imports during builds must not open Postgres or demand runtime secrets. Better-auth supplies the session identity; mutation handlers pass that identity to Drizzle rather than accepting a body-owned tenant. Reviews insert idempotently by ID; metadata upserts require a strictly newer timestamp. Saved/custom review and membership writes additionally check deck ownership. [context.ts:13–27](https://github.com/harryt04/kanji-forge/blob/c6c90e354db9cb4605cf7d46a95eccf57d261adf/src/server/context.ts#L13-L27), [mutations route:17–44](https://github.com/harryt04/kanji-forge/blob/c6c90e354db9cb4605cf7d46a95eccf57d261adf/src/app/api/mutations/route.ts#L17-L44), [server/mutations.ts:246–355](https://github.com/harryt04/kanji-forge/blob/c6c90e354db9cb4605cf7d46a95eccf57d261adf/src/server/mutations.ts#L246-L355)

The outbox supports five mutation types, batches at most 100, deletes only acknowledgements, backs off on transport failures, pauses on 401, and quarantines rejected rows in memory. Unsupported types remain queued. Two static gaps mean the intended architecture should not be described as proven end-to-end sync:

- Study grades enqueue only `{deckId, contentRef, grade, at}`, and undo has another abbreviated payload. Server review validation requires `id`, levels, timing, source, and device fields. Since validation maps the entire batch before applying it, these writes imply a 400 for the batch and session quarantine. The complete server test fixture does not exercise the store-produced payload. Fractional `elapsedDays` also conflicts with server integer validation. [server/mutations.ts:140–164](https://github.com/harryt04/kanji-forge/blob/c6c90e354db9cb4605cf7d46a95eccf57d261adf/src/server/mutations.ts#L140-L164), [mutations.test.ts:8–35](https://github.com/harryt04/kanji-forge/blob/c6c90e354db9cb4605cf7d46a95eccf57d261adf/src/server/mutations.test.ts#L8-L35)
- Once an initial flush sees an empty queue, it returns without scheduling another. Production starts the worker at bootstrap and wakes it on `online`; grade insertion has no enqueue notification or call to `flush()`. Thus newly created online mutations can wait until another lifecycle/network event. These are source-derived findings, not reproduced runtime failures. [outbox/index.ts:118–139](https://github.com/harryt04/kanji-forge/blob/c6c90e354db9cb4605cf7d46a95eccf57d261adf/src/data/outbox/index.ts#L118-L139), [outbox/index.ts:234–260](https://github.com/harryt04/kanji-forge/blob/c6c90e354db9cb4605cf7d46a95eccf57d261adf/src/data/outbox/index.ts#L234-L260)

Read sync defaults to the authenticated `/api/sync` snapshot every 15 seconds. Electric is optional behind a build-time client gate and runtime server configuration. Its proxy allowlists tables, overwrites the client filter with parameterized `user_id = $1`, and retains the secret server-side. The client buffers each response, materializes five projections, and falls back to snapshots on failure or handle rotation. Review union and metadata timestamp merges use `restoreBackup()` in both transports. [sync/index.ts:45–69,112–188](https://github.com/harryt04/kanji-forge/blob/c6c90e354db9cb4605cf7d46a95eccf57d261adf/src/data/sync/index.ts#L45-L188), [electric.ts:29–51](https://github.com/harryt04/kanji-forge/blob/c6c90e354db9cb4605cf7d46a95eccf57d261adf/src/server/electric.ts#L29-L51)

`card_states` deliberately never reaches Postgres. Merge replays the entire union using default SRS configuration, deduplicated IDs, timestamp/ID ordering, absolute manual overrides, and seeded fuzz. This has consequences beyond transport: replay does not retain adaptive due dates or flags, while live scheduling uses unseeded fuzz and the session queue's red count. Flag writes use unsupported `cardState.upsert`. Restore can therefore replace local projection details even when the log survives. Review this seam before changing scheduling or claiming exact device continuity. [repo/index.ts:994–1068](https://github.com/harryt04/kanji-forge/blob/c6c90e354db9cb4605cf7d46a95eccf57d261adf/src/data/repo/index.ts#L994-L1068), [replay.ts:19–66](https://github.com/harryt04/kanji-forge/blob/c6c90e354db9cb4605cf7d46a95eccf57d261adf/src/core/srs/replay.ts#L19-L66)

## Account, content, and recovery boundaries

Account switching stops both workers and closes the previous database before opening the next namespace. Logout tears down local runtime before the network request and clears cached identity even offline; it retains the user's on-disk database. `getSession()` permits cached identity on network or JSON failure, which is local availability policy, not server authorization. OPFS namespacing is isolation within the application, not encryption. [runtime.ts:13–49](https://github.com/harryt04/kanji-forge/blob/c6c90e354db9cb4605cf7d46a95eccf57d261adf/src/auth/runtime.ts#L13-L49), [client.ts:46–69,109–112](https://github.com/harryt04/kanji-forge/blob/c6c90e354db9cb4605cf7d46a95eccf57d261adf/src/auth/client.ts#L46-L112)

Content is shared, immutable, and separately licensed. Runtime fetches the full deck catalog from `/packs/decks/catalog.json`, but core SQLite/stroke content from `/packs-dev/`; do not assume generated full-size packs are automatically published. ETL entry points are individual `build-*` scripts and `pipeline.mjs`, not leftover `index.ts`. Source locks pin data and license hashes; changed license text aborts before lock replacement unless explicitly approved. Assertions enforce manifests, budgets, record drift, and prohibited SKIP fields; monthly reproducibility rebuilds locked sources twice. [packs/index.ts:110–122,313–335](https://github.com/harryt04/kanji-forge/blob/c6c90e354db9cb4605cf7d46a95eccf57d261adf/src/data/packs/index.ts#L110-L335), [fetch-sources.ts:769–785](https://github.com/harryt04/kanji-forge/blob/c6c90e354db9cb4605cf7d46a95eccf57d261adf/scripts/build-packs/fetch-sources.ts#L769-L785)

Project policy separates MIT code from CC BY-SA derived data, with source-specific attribution retained for KanjiVG/Tatoeba and three attribution surfaces: repository, offline Settings, manifests. Commercial audio, RTK, SKIP, and reproduced NHK text are excluded. These are repository policy observations, not newly verified legal conclusions. [DATA-SOURCES.md:85–124,270–303](https://github.com/harryt04/kanji-forge/blob/c6c90e354db9cb4605cf7d46a95eccf57d261adf/docs/DATA-SOURCES.md#L85-L303)

Version-1 JSON backups include reviews, decks, membership, settings, and annotations, validate account ownership, and merge rather than replace. They omit sessions, daily statistics, outbox, card-state-only flags, installed packs, and folder handles. Restore creates no new outbox rows, so restored local history is not thereby uploaded. Optional folder backups store handles per user in IndexedDB and overwrite one file at most daily when foregrounded. Sync cannot replace this eviction-recovery boundary. [backup.ts:26–101](https://github.com/harryt04/kanji-forge/blob/c6c90e354db9cb4605cf7d46a95eccf57d261adf/src/features/settings/backup.ts#L26-L101), [auto-backup.ts:164–224](https://github.com/harryt04/kanji-forge/blob/c6c90e354db9cb4605cf7d46a95eccf57d261adf/src/features/settings/auto-backup.ts#L164-L224)
