## Purpose and current shape

VoiceBridge helps autistic children/adults communicate through named visual cards and an AAC symbol/phrase board. Caregivers manage speaker profiles; villagers share access. It is a Next.js App Router application with React, direct MongoDB, better-auth, React Query, and browser speech synthesis. Foods, activities, vocabulary, people and places are speaker-scoped resources; music is explicitly “coming soon,” despite landing-page promises about calming playlists ([music page, lines 1–8](https://github.com/harryt04/voice-bridge/blob/375794356ede3610f3ebf807448de6edcbd53f99/app/music/page.tsx#L1)). This is a communication aid, with no inspected implementation of streaming music or clinical workflows.

## Speaker/profile and sharing flow

`SpeakerProvider` queries `/api/speakers`, selects the first result, and distributes selection through context. The endpoint authenticates, lists nonarchived speakers where the session user is parent or villager, and creates a default profile when none exist. That GET therefore writes; its insert is not awaited, and concurrent empty-list requests can create defaults independently ([speaker listing, lines 5–55](https://github.com/harryt04/voice-bridge/blob/375794356ede3610f3ebf807448de6edcbd53f99/app/api/speakers/route.ts#L5)).

The same request sends session email plus `usesApps: ['voicebridge']` to the shared portfolio CRM endpoint `https://harryt.dev/api/user`. This is a cross-project personal-information boundary, not an auth dependency: the POST is fire-and-forget, rejected promises are swallowed, and HTTP failure statuses are not checked. CRM implementation, retention and deduplication were outside scope.

Profile forms POST to `/api/speaker[?id=…]`; the selector consumes `updatedSpeaker` without checking HTTP status. UI deletion archives via POST and reloads `/places`; the API also offers physical DELETE without cascading child resources. Existing parent **or villager** may modify/delete a profile. Crucially, server defaults `parentId` before spreading the body, allowing a caller-supplied value to overwrite ownership; profile insertion is also unawaited ([speaker route, lines 55–156](https://github.com/harryt04/voice-bridge/blob/375794356ede3610f3ebf807448de6edcbd53f99/app/api/speaker/route.ts#L55)). Sharing ultimately calls activation, which checks login and speaker existence then adds the requester to `villagerIds`; there is no invitation approval or separate token check. Knowledge of a speaker ID is sufficient to join ([activation, lines 6–38](https://github.com/harryt04/voice-bridge/blob/375794356ede3610f3ebf807448de6edcbd53f99/app/api/speaker/activate/route.ts#L6)).

## Cards, CRUD and ownership invariants

Generic pages fetch a selected speaker’s plural endpoint into component state. Item forms collect text/image data; singular POST creates or updates; tapping a card speaks its name. Central CRUD authenticates, resolves the stored item for ID-based operations, checks its speaker membership, and records server-controlled updater/time. Lists filter by `speakerId`. Thus the documentation’s “ignored authorization” warning is stale: denial responses are actually returned ([Mongo helpers, lines 21–204](https://github.com/harryt04/voice-bridge/blob/375794356ede3610f3ebf807448de6edcbd53f99/lib/mongo-utils.ts#L21)).

The remaining invariant gaps matter: generic mutation permissions do not distinguish parent from villager; arbitrary body fields are spread into storage; updates authorize the **old** speaker but can replace `speakerId` without checking the destination. Missing update IDs create rather than strictly requiring an existing item. Invalid ObjectIds commonly become 500s. Places duplicate this logic in their own route, so shared-helper fixes do not automatically cover them.

Client reconciliation is weaker than persistence. Generic delete removes local data without checking response status; child cards also issue DELETE, producing duplicate requests. Card edits update local state before an unchecked POST. There is no rollback, and component-local card state can diverge from page data ([generic page, lines 44–103](https://github.com/harryt04/voice-bridge/blob/375794356ede3610f3ebf807448de6edcbd53f99/components/custom/generic-items-page.tsx#L44); [card mutations, lines 61–75](https://github.com/harryt04/voice-bridge/blob/375794356ede3610f3ebf807448de6edcbd53f99/components/custom/item-component.tsx#L61)).

## AAC board and cache consistency

AAC layout fetches preferences per speaker and holds an in-memory sentence across child navigation; it has no speaker-change reset. Categories resolve a symbol provider; taps append words and optionally speak, while phrase taps either append or speak. Speech cancels the previous utterance, uses installed browser voices, and catches failures. Default phrases merge with saved custom phrases. API reads allow parent/villager; AAC mutations use Zod plus a separate parent-only auth helper. Phrase updates additionally check stored phrase ownership ([AAC auth, lines 32–68](https://github.com/harryt04/voice-bridge/blob/375794356ede3610f3ebf807448de6edcbd53f99/lib/aac/aac-auth.ts#L32)).

The UI is less complete than those APIs: phrase-page Add is empty, and edit/delete callbacks are not supplied to the grid. Preferences save only the changed field after 300ms, but the server schema requires the full settings object, including string-valued grid columns. The mutation neither updates nor invalidates the query, leaving controlled values tied to stale context ([settings form, lines 38–78](https://github.com/harryt04/voice-bridge/blob/375794356ede3610f3ebf807448de6edcbd53f99/components/custom/aac-settings-form.tsx#L38); [validator, lines 15–33](https://github.com/harryt04/voice-bridge/blob/375794356ede3610f3ebf807448de6edcbd53f99/lib/aac/aac-validators.ts#L15)). These are source-inferred defects, not reproduced failures.

AAC query keys include speaker ID; the speaker-list key is only `['speakers']`. Its setter directly pushes into query-owned arrays and does not replace edited entries or invalidate queries. Legacy cards bypass React Query entirely. Account-switch isolation, profile refresh and rapid speaker-switch fetch races deserve review ([speaker context, lines 24–57](https://github.com/harryt04/voice-bridge/blob/375794356ede3610f3ebf807448de6edcbd53f99/hooks/use-speakers.tsx#L24)). No durable offline queue/service-worker behavior was found in inspected flows.

## Integration and delivery boundaries

Uploads are browser FileReader/canvas JPEG conversion (800×800 bounds, quality 0.7), stored as base64 in Mongo documents; external image URLs are also supported. This is not object-storage uploading. Next image configuration allows any HTTPS hostname. Directions open an encoded destination in Google Maps, without an app geolocation/API-key flow. Mulberry supplies local symbols; ARASAAC/custom fall back to it. OpenSymbols supplies search only, through an authenticated server proxy with server-held secret, instance token cache, 24-hour search fetch caching and one retry after 401. Its category provider returns empty. Full-URL fetch logging warrants attention because upstream search URLs contain access tokens ([proxy, lines 27–97](https://github.com/harryt04/voice-bridge/blob/375794356ede3610f3ebf807448de6edcbd53f99/app/api/aac/symbols/search/route.ts#L27); [Next config, lines 1–33](https://github.com/harryt04/voice-bridge/blob/375794356ede3610f3ebf807448de6edcbd53f99/next.config.js#L1)). PostHog runs in production through `/ingest` rewrites.

Auth supports password and Google OAuth, with a separate Mongo client and transactions explicitly disabled for a standalone server. Application/auth databases use `voicebridge-${NODE_ENV}`; staging separation needs deliberate configuration. Index creation covers speaker lookups and unique AAC preferences per speaker.

Manifest commands: `npm run ci` checks formatting, ESLint, Next build and Vitest; `test:watch`, `dev`, `start`, and mutating `prettify`/`prep` also exist. PR CI targets master on Node 24, runs `npm ci` then `npm run ci` ([workflow](https://github.com/harryt04/voice-bridge/blob/375794356ede3610f3ebf807448de6edcbd53f99/.github/workflows/ci.yml#L1)). Vitest separates node/jsdom, uses memory Mongo and disables file parallelism. Route/helper tests cover authorization, but browser end-to-end delivery was not demonstrated. `TEST_SETUP_STATUS.md`’s 159/159 claim is historical, not verified here. README recommends Coolify or Vercel; no inspected automated deployment workflow proves current hosting. Docs still mention Clerk, `next lint`, and nonexistent config filenames; consult executable manifests/source before following recipes.
