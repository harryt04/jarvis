## Purpose and current state

MailFlow is an installable, mobile-first Gmail reader for people overwhelmed by their inbox. Its distinctive workflow is sequential listening with spoken decisions between chunks, persistent email-level progress, and dictated replies read back before sending. It targets friends/family scale and ordinary browser/OS audio output, including already-paired Bluetooth devices. Gmail-only, PWA-only, online operation and no simultaneous mic/playback remain meaningful boundaries; search and custom-label moves have since exceeded the original PRD's narrower non-goals. The PRD is historical intent, not a complete description of today's feature surface. [PRD:7–32](https://github.com/harryt04/mail-flow/blob/bde567c4c80818ff08e82b64a503847e75889975/mvp-docs/PRD.md#L7-L32)

The implemented stack is Next 16.2.10, React 19.2.4, NextAuth 5 beta, raw MongoDB, `googleapis`, and OpenAI; Node **24+** is declared. Current speech synthesis uses `gpt-4o-mini-tts`/`alloy`, batch transcription uses `gpt-4o-mini-transcribe`, and reply cleanup uses `gpt-4o-mini`. Deepgram/Anthropic recommendations and streaming designs in `mvp-docs/` are superseded implementation history. ## Architecture and traced boundaries

**Google login → application identity → Gmail client.** One consent requests OpenID/profile/email and `gmail.modify`, offline access and renewed consent. The JWT callback requires both Google access/refresh tokens, ensures indexes, upserts by Google subject, encrypts tokens, seeds settings on insert, and places only the database user ID into the application JWT/session. Missing refresh tokens fail login with revocation/reconsent guidance. Proxy gating protects page prefixes and all APIs except NextAuth; route-level `requireUser()` independently resolves the session ID to an ObjectId. Gmail access belongs to `lib/gmail/client.ts`, which decrypts that user's stored credentials and delegates refresh to Google's OAuth client. Its token event persists updates best-effort; failed persistence is swallowed. Application login validity and usable/revoked Gmail authorization are therefore separate concerns. [Auth:8–84](https://github.com/harryt04/mail-flow/blob/bde567c4c80818ff08e82b64a503847e75889975/src/lib/auth/options.ts#L8-L84), [proxy:7–49](https://github.com/harryt04/mail-flow/blob/bde567c4c80818ff08e82b64a503847e75889975/src/proxy.ts#L7-L49), [guard:9–17](https://github.com/harryt04/mail-flow/blob/bde567c4c80818ff08e82b64a503847e75889975/src/lib/auth/requireUser.ts#L9-L17), [client:19–57](https://github.com/harryt04/mail-flow/blob/bde567c4c80818ff08e82b64a503847e75889975/src/lib/gmail/client.ts#L19-L57)

**Inbox settings → immutable snapshot → checkpoint/resume.** `/api/session` POST loads user settings, obtains Gmail context and composes `getOrCreateActiveSession` with `buildCheckpointResponse`. Defaults are unread, oldest-first, Primary. Snapshot queries always include `INBOX`; a custom label overrides category, unread adds `is:unread`, and newest-first results are reversed for oldest order. Pagination is 500 IDs/page capped at 20,000, with Gmail's approximate total separately exposed. Thus oldest-first over a capped inbox means oldest within the fetched newest 20,000, not necessarily oldest globally. Matching scope/order/category/label resumes an active snapshot; changed settings exhaust it and create another. New mail is incorporated on a subsequent snapshot. [Session route:36–65](https://github.com/harryt04/mail-flow/blob/bde567c4c80818ff08e82b64a503847e75889975/src/app/api/session/route.ts#L36-L65), [defaults:113–120](https://github.com/harryt04/mail-flow/blob/bde567c4c80818ff08e82b64a503847e75889975/src/lib/types.ts#L113-L120), [listing:9–77](https://github.com/harryt04/mail-flow/blob/bde567c4c80818ff08e82b64a503847e75889975/src/lib/gmail/list.ts#L9-L77), [session ownership:46–111](https://github.com/harryt04/mail-flow/blob/bde567c4c80818ff08e82b64a503847e75889975/src/lib/bookmark/session.ts#L46-L111)

Mongo owns users, sessions, bookmarks and action logs. The cursor on the active session drives actual resume; bookmark documents hold the active-session reference and last processed ID. Checkpoint construction optionally advances/logs category auto-skips, then fetches the full current email. Parsing prefers plain text, falls back to stripped HTML, removes quoted-history markers, humanizes URLs and splits paragraphs. Email bodies are fetched when needed rather than stored as a mailbox replica. Progress is persisted **per email action**, not per spoken paragraph: closing mid-email restarts that email. Inbox browsing fetches only one metadata page, while “Start here” validates session ownership and snapshot membership before setting the cursor. Search queries live Gmail with category but omit snapshot unread/custom-label filters, so a search result can legitimately fail that membership check. [Collections:17–55](https://github.com/harryt04/mail-flow/blob/bde567c4c80818ff08e82b64a503847e75889975/src/lib/db/collections.ts#L17-L55), [checkpoint/jump:188–289](https://github.com/harryt04/mail-flow/blob/bde567c4c80818ff08e82b64a503847e75889975/src/lib/bookmark/session.ts#L188-L289), [parser:126–149](https://github.com/harryt04/mail-flow/blob/bde567c4c80818ff08e82b64a503847e75889975/src/lib/gmail/parse.ts#L126-L149), [inbox:22–77](https://github.com/harryt04/mail-flow/blob/bde567c4c80818ff08e82b64a503847e75889975/src/app/api/inbox/route.ts#L22-L77), [search:138–160](https://github.com/harryt04/mail-flow/blob/bde567c4c80818ff08e82b64a503847e75889975/src/lib/gmail/list.ts#L138-L160)

**Listening → command → Gmail mutation/reconciliation.** `ListenClient` orchestrates lifecycle, voice/reply/move states and generation-based cancellation; domain work belongs under `lib/`. It speaks sender/subject, asks before body playback, then combines short paragraphs until three sentences or 50 words, subject to remaining content. `useAudioPlayback` fetches TTS into an audio blob; `useVoiceSession` subsequently captures PCM through an AudioWorklet, uses RMS silence detection, encodes WAV at the actual device sample rate, and posts a whole clip to the server. Default capture is four seconds of silence/20 seconds maximum; dictation uses 1.5 seconds/60 seconds. The browser never receives provider credentials. Two silent checkpoint attempts pause; four unrecognized attempts fall back to buttons. Pause and paragraph position are client state. Cancellation aborts STT fetch and invalidates continuations, but does not undo an already-submitted server action. [Listen orchestration:590–838](https://github.com/harryt04/mail-flow/blob/bde567c4c80818ff08e82b64a503847e75889975/src/app/(authenticated)/listen/ListenClient.tsx#L590-L838), [audio:33–100](https://github.com/harryt04/mail-flow/blob/bde567c4c80818ff08e82b64a503847e75889975/src/hooks/useAudioPlayback.ts#L33-L100), [capture:113–283](https://github.com/harryt04/mail-flow/blob/bde567c4c80818ff08e82b64a503847e75889975/src/hooks/useVoiceSession.ts#L113-L283)

Archive and spoken “delete” both remove `INBOX`; nothing is permanently deleted. Skip removes `UNREAD` before advancement. Move adds a label and archives; voice matching and manual picking both confirm the target. Reply captures dictation, cleans it, speaks the cleaned draft, and requires confirm/redo; manual Send can submit edited text. Sending preserves Gmail thread ID and RFC reply/reference headers. These confirmations are UI behavior: the reply endpoint accepts nonempty text without a server-side confirmation record. Snooze remains in types/docs but has no command or route in this checkout. ## Security, metering and failure invariants

Credentials use AES-256-GCM, fresh 12-byte IVs and a base64 environment key decoding to 32 bytes. BYOK validation calls OpenAI's model list before encrypting the key; GET returns presence/counts only. The saved key always wins, otherwise the server trial key applies while usage is below 100. Successful archive/delete/move/reply increments usage unconditionally, including BYOK operation; skip and AI requests do not. This is an action proxy, **not an AI-call or spending quota**: repeated reading/transcribing/cleanup need not consume actions. AI routes reject missing credentials; the page layout redirects exhausted users without keys to onboarding. [Crypto:4–46](https://github.com/harryt04/mail-flow/blob/bde567c4c80818ff08e82b64a503847e75889975/src/lib/auth/tokenCrypto.ts#L4-L46), [BYOK endpoint:23–88](https://github.com/harryt04/mail-flow/blob/bde567c4c80818ff08e82b64a503847e75889975/src/app/api/settings/openai-key/route.ts#L23-L88), [resolution/counter:18–46](https://github.com/harryt04/mail-flow/blob/bde567c4c80818ff08e82b64a503847e75889975/src/lib/auth/openaiKey.ts#L18-L46), [layout:19–33](https://github.com/harryt04/mail-flow/blob/bde567c4c80818ff08e82b64a503847e75889975/src/app/(authenticated)/layout.tsx#L19-L33)

Gmail effects precede metering, cursor advancement and next-message fetching. Routes validate strings but construct session ObjectIds after the Gmail effect. `advanceSession` checks user/session ownership, yet neither current-message equality nor active status; its atomic increment, bookmark update and log insertion are separate operations. Consequently stale/double submissions or partial failures can advance twice, misattribute progress, or resend a reply on retry. There is no observed application idempotency/reconciliation layer or unique active-session index. Missing/deleted snapshot messages fail fetching rather than being automatically repaired. These are static failure-path inferences, not reproduced incidents. [Archive ordering:18–44](https://github.com/harryt04/mail-flow/blob/bde567c4c80818ff08e82b64a503847e75889975/src/app/api/actions/archive/route.ts#L18-L44), [advance:128–179](https://github.com/harryt04/mail-flow/blob/bde567c4c80818ff08e82b64a503847e75889975/src/lib/bookmark/session.ts#L128-L179)

Email text leaves the app for TTS, recorded voice for STT, and dictated text for cleanup. Reply text and label names are persisted unencrypted in action logs. Disconnect attempts Google revocation best-effort and deletes users/bookmarks/sessions, **retaining logs**, including reply text; no expiry is defined in the inspected indexes. TTS returns `no-store`; the service worker caches only static assets/fonts, never API data or navigations, so installability does not imply offline email. [Log fields:167–176](https://github.com/harryt04/mail-flow/blob/bde567c4c80818ff08e82b64a503847e75889975/src/lib/bookmark/session.ts#L167-L176), [disconnect:9–45](https://github.com/harryt04/mail-flow/blob/bde567c4c80818ff08e82b64a503847e75889975/src/app/api/settings/disconnect/route.ts#L9-L45), [worker:24–49](https://github.com/harryt04/mail-flow/blob/bde567c4c80818ff08e82b64a503847e75889975/public/sw.js#L24-L49), [TTS response:37–42](https://github.com/harryt04/mail-flow/blob/bde567c4c80818ff08e82b64a503847e75889975/src/app/api/tts/route.ts#L37-L42)

## Delivery, decisions and future navigation
