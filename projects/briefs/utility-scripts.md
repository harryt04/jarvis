## Package-update flow and ownership

`update_dependencies` owns the mutation sequence: display cwd, run `npx update-browserslist-db@latest`, install `posthog-js posthog-node` plus optional arguments, run `npm audit fix`, commit tracked changes, and push ([update-packages.sh:1–15](https://github.com/harryt04/utility-scripts/blob/ab8845b31b655f5d4e71ce4eb040e03fcf1724f4/update-packages.sh#L1-L15)). This updates browser compatibility data and npm dependency state in the current directory. It installs analytics client/server dependencies; it does not configure or invoke analytics itself. The install and audit steps can alter manifests, lockfiles, and installed dependencies, and npm's normal lifecycle behavior can execute target dependency code. `npx ...@latest` makes future execution dependent on newly resolved external code. Exact resulting versions and network effects cannot be inferred from this repository alone.

The top-level procedure serially enters nine hard-coded directories below `~/Documents/git`. Grub Roulette, Rise Above Drone, and Route Roulette receive the base install; Portfolio additionally receives `mongodb`; Scaffolding, Pantry IQ App, Tokei, and Voicebridge receive `mongodb better-auth`; Pantry IQ Landing receives the base install ([update-packages.sh:17–42](https://github.com/harryt04/utility-scripts/blob/ab8845b31b655f5d4e71ce4eb040e03fcf1724f4/update-packages.sh#L17-L42)). The extra arguments describe package choices, not proof that those projects currently use those integrations. The optional string is intentionally expanded unquoted into separate shell words, but also admits pathname expansion. Only `$1` is captured, so the existing quoted caller strings matter.

The helper has no subshell or directory argument: callers own cwd, and every operation inherits it. Neither file has a shebang. Shell selection is therefore implicit; sourcing the updater also changes the caller's cwd and defines functions/variables there. There is no entry-point guard.

## Failure, commit, and push boundaries

There is no `set -e`, guarded `cd`, explicit status check, or stop-on-error branch. A failed npm command does not prevent commit or push; a failed commit does not prevent pushing pre-existing local commits; a failed push does not prevent moving to the next project. Terminal output is the only recorded diagnostic. The commit message always claims a dependency/audit update, irrespective of preceding success.

`git commit -am` stages modifications and deletions to tracked files, including unrelated work already present, and includes already-staged changes. It does not add new untracked files such as a newly generated lockfile. Thus a successful command is not evidence of a complete or correctly scoped dependency commit. There is no clean-worktree check, diff review, test, or per-repository approval boundary. `git push` names neither remote nor branch: behavior depends on Git configuration, upstream tracking, credentials, and current checkout. No checkout, fetch, default-branch discovery, or synchronization occurs. The source repository being on `master` does not establish that target repositories should use `master`, or that the updater runs on their default branches.

A local filesystem-only check found both `pantry-iq-landing` and `pantry-iq-app` absent; the other seven named directories and their `.git` markers were present. These are observation-time facts, not portable requirements or validation of those repositories. In this layout, after Scaffolding, both failed Pantry IQ `cd` operations would leave cwd in Scaffolding and invoke the helper there again. If the first `cd` fails, the initial caller directory becomes the mutation target. This is the most consequential implicit invariant: every directory transition must succeed before any package or Git operation is safe.

## One-off procedures and data boundaries

`one-off-commands.sh` is an operations scratchpad, not a coherent executable flow. Its initial root-host prompt and bare Plex database path are context notes, not navigation commands. The relative `DBRepair.sh` invocation supplies a relative Plex SQLite tool and `./` databases, so it requires an externally prepared cwd and external repair tooling absent here ([one-off-commands.sh:1–5](https://github.com/harryt04/utility-scripts/blob/ab8845b31b655f5d4e71ce4eb040e03fcf1724f4/one-off-commands.sh#L1-L5)). Repair semantics, backup expectations, and compatibility cannot be established without that tool; database contents were not accessed.

The next procedure overwrites a local `chapters.txt`, then runs ffmpeg inside an existing named Docker container to concatenate audio into an AAC `.m4b` at container-specific media paths ([lines 7–14](https://github.com/harryt04/utility-scripts/blob/ab8845b31b655f5d4e71ce4eb040e03fcf1724f4/one-off-commands.sh#L7-L14)). The escaped star in `Chapter\*.mp3` is literal: it does not enumerate chapter files as written. Host output location, container mount mapping, ordering, and valid concat entries must be reconciled independently. `-safe 0` permits otherwise restricted concat paths; output overwrite policy is not explicitly supplied.

The disk-usage pipeline suppresses errors and returns twenty entries despite its “TOP 50” comment. Two `fdupes` commands mix summarization/recursive traversal with deletion options; the second explicitly combines recursive deletion with no prompt ([lines 16–25](https://github.com/harryt04/utility-scripts/blob/ab8845b31b655f5d4e71ce4eb040e03fcf1724f4/one-off-commands.sh#L16-L25)). Its historical duplicate-count comment is not a current measurement. Exact installed utility versions and flag semantics were not verified. The root context and broad mounted-media paths make these procedures consequential storage operations. No secret values or media/database contents are needed to understand them.
