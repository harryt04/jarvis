## Product and present boundaries

HairnThere is Elisabeth’s neighborhood hair-services website for Suncrest in Draper, Utah, and nearby communities. Visitors discover her work, browse prices, share household needs, and contact her for manual planning. Elisabeth receives inquiries in Discord and confirms details personally. The site is also a QR-first business card for in-person introductions. It has no accounts, calendar reservations, checkout, deposits, automated follow-up, mailing-list enrollment, or operating vehicle salon. The Subaru is decorative branding. Location/licensing authorization is an external business prerequisite; website wording is not evidence that permission has been independently verified. See [`availability.ts:3–41`](https://github.com/harryt04/hair-n-there/blob/400832fbcec8779116e320f9928aa7267c2d5eed/src/data/availability.ts#L3-L41) and [`terms/page.tsx:31–81`](https://github.com/harryt04/hair-n-there/blob/400832fbcec8779116e320f9928aa7267c2d5eed/src/app/%28site%29/terms/page.tsx#L31-L81).

House-call inquiries are open, but appointment requests are rejected; the actual form chooses consultation intent. ## Architecture and ownership

One root pnpm application uses Next.js 16.4.4 App Router, React 19.3.1, TypeScript, Tailwind 4, generated shadcn/Base UI components, next-themes, Embla, Zod, and PostHog. Server-rendered pages own menu/portfolio content; client components handle form state, carousel controls, motion, installation, and telemetry. The root layout supplies fonts, themes, PWA support, and telemetry. `(site)` adds header, Mountain Cinema ribbon, and footer; `/card` bypasses that chrome. There is no application database, queue, durable idempotency store, or messaging worker. ## Three source-traced flows

**Menu → editable interest → acknowledged inquiry.** `/services` renders all categories and bundles, including `+`, `/row`, consultation/free distinctions, and supplied durations. Links carry `?service=ID` or `?package=ID`. `ContactEntry` resolves only known IDs, with service taking precedence, and initializes a visible editable selection. The three stages collect overlapping haircut/color counts, optional date and time preference, address, then name and phone and/or email. A person receiving both services appears in both counts. The selected interest has quantity one; counts do not become priced catalog quantities or package allocations. [`services/page.tsx:20–31,97–174`](https://github.com/harryt04/hair-n-there/blob/400832fbcec8779116e320f9928aa7267c2d5eed/src/app/%28site%29/services/page.tsx#L20-L174), [`contact-form.tsx:27–149`](https://github.com/harryt04/hair-n-there/blob/400832fbcec8779116e320f9928aa7267c2d5eed/src/components/contact/contact-form.tsx#L27-L149).

Client validation blocks advancing past relevant errors and moves focus to error/stage/success content. The shared strict schema rejects unknown fields, bounds service lines/quantities, validates real dates and times, requires at least one valid contact method, and requires both counts plus address for the normal house flow. The server additionally validates catalog IDs. `/api/contact` rejects cross-site requests and non-JSON, rate-limits before body reading, bounds the body to 16 KiB with a five-second deadline, rejects the honeypot, and enforces shared availability regardless of browser flags. [`inquiry-validation.ts:13–179`](https://github.com/harryt04/hair-n-there/blob/400832fbcec8779116e320f9928aa7267c2d5eed/src/lib/inquiry-validation.ts#L13-L179), [`api/contact/route.ts:82–159`](https://github.com/harryt04/hair-n-there/blob/400832fbcec8779116e320f9928aa7267c2d5eed/src/app/api/contact/route.ts#L82-L159).

Discord URLs are restricted to HTTPS Discord webhook hosts/paths. Preview selects only the preview webhook, with no production fallback. Delivery escapes Markdown/mentions, disables mentions explicitly, places the address in a private text attachment, and clips embed previews while preserving full details. `wait=true`, an OK response, and a returned message ID are required before success. Errors retain browser input. An uncertain timeout can mean delivery already happened; retry can duplicate it because there is no durable idempotency or automatic resend. [`discord.ts:14–41,100–132,185–226`](https://github.com/harryt04/hair-n-there/blob/400832fbcec8779116e320f9928aa7267c2d5eed/src/lib/discord.ts#L14-L226), [`contact-form.tsx:189–232`](https://github.com/harryt04/hair-n-there/blob/400832fbcec8779116e320f9928aa7267c2d5eed/src/components/contact/contact-form.tsx#L189-L232).

## Data and integration constraints

The limiter hashes network addresses and allows five attempts per 600 seconds. Optional Upstash Redis provides shared limits; incomplete/unavailable configured Redis fails closed. The fallback retains at most 2,000 process-local buckets and cannot enforce a global serverless limit. Do not log customer payloads, credentials, webhook URLs, or provider responses. [`rate-limit.ts:3–83`](https://github.com/harryt04/hair-n-there/blob/400832fbcec8779116e320f9928aa7267c2d5eed/src/lib/rate-limit.ts#L3-L83).

Providing a phone number sets `phoneContactConsent` in the public form, even with email present; it never sets legacy `smsConsent`. Discord records disclosure/version/time/source separately. Legacy SMS validation remains, but durable consent/opt-out enforcement and any automated provider remain future work. Analytics initializes only with a token and `NEXT_PUBLIC_VERCEL_ENV=production`; identifiers stay in memory. Event/property allowlists remove inquiry data, query strings, fragments, attribution, and detailed referrers. Replay, autocapture, identified profiles, and exception capture are disabled. `/ingest` proxies PostHog Cloud US through Vercel; PostHog is not self-hosted. [`business.ts:16–22`](https://github.com/harryt04/hair-n-there/blob/400832fbcec8779116e320f9928aa7267c2d5eed/src/data/business.ts#L16-L22), [`analytics.ts:6–47`](https://github.com/harryt04/hair-n-there/blob/400832fbcec8779116e320f9928aa7267c2d5eed/src/lib/analytics.ts#L6-L47), [`analytics-policy.ts:85–151`](https://github.com/harryt04/hair-n-there/blob/400832fbcec8779116e320f9928aa7267c2d5eed/src/lib/analytics-policy.ts#L85-L151).

PWA installation does not enable offline inquiries. The worker caches only `/offline.html`, passes POST/API/RSC through, and waits for existing windows to close before updating. Bump its cache version when changing that page. [`public/sw.js:1–59`](https://github.com/harryt04/hair-n-there/blob/400832fbcec8779116e320f9928aa7267c2d5eed/public/sw.js#L1-L59).
