## Purpose and state

Harry's B.S. capstone replaces the MiniZinc desktop IDE with a browser editor: Google sign-in, cloud projects/files, email-based sharing, solver flags, remote execution, and shared console output. The README explicitly supports Chrome only and warns that local development uses the same Firebase project as production; forks should supply their own configuration. These are historical project decisions, not general browser or development preferences. This is substantial implemented application source, but archival status and source inspection provide no evidence that its advertised hosting or solver server still works. ## Ownership and actual flows

The frontend is Vue 2, Vue Router, Vuex, Vuetify 1, Firebase's browser SDK, Axios, and an Ace wrapper. `ide.vue` owns most UI and interaction logic; `store.js` owns Firestore operations and selected indexes. MiniZinc syntax highlighting is an Ace mode copied into `node_modules/brace/mode` by frontend `postinstall`. This is editor highlighting, not an in-browser solver. Express separately owns the native solver boundary. [frontend/package.json:6–27](https://github.com/harryt04/minizinc-web/blob/282c9bf2ea853ae0582bb3a78c11180c28700e72/frontend/package.json#L6-L27), [mzn.js:1–21](https://github.com/harryt04/minizinc-web/blob/282c9bf2ea853ae0582bb3a78c11180c28700e72/frontend/src/assets/mzn.js#L1-L21).

**Sign-in and discovery.** Firebase initialization delays mounting Vue until its first auth-state callback. Google redirect sign-in and route guards send authenticated users to `/` and others to `/login`. The IDE's own auth listener dispatches Vuex `signIn`. The store reads `users/{uid}`, loads existing users' projects, or creates a sample model/data project for a new user, then stores display name, email, photo URL, and UID. Project access is represented by `owner` email and `collaborators` email array, queried separately. These client queries describe discovery, not proof of server-enforced authorization. [main.js:20–40](https://github.com/harryt04/minizinc-web/blob/282c9bf2ea853ae0582bb3a78c11180c28700e72/frontend/src/main.js#L20-L40), [gaurds.js:1–10](https://github.com/harryt04/minizinc-web/blob/282c9bf2ea853ae0582bb3a78c11180c28700e72/frontend/src/router/gaurds.js#L1-L10), [store.js:51–115](https://github.com/harryt04/minizinc-web/blob/282c9bf2ea853ae0582bb3a78c11180c28700e72/frontend/src/store.js#L51-L115), [ide.vue:950–957](https://github.com/harryt04/minizinc-web/blob/282c9bf2ea853ae0582bb3a78c11180c28700e72/frontend/src/components/ide.vue#L950-L957).

**Editing and collaboration.** Projects embed their entire `files` array; files carry name, random client ID, and code. Editor changes and a code watcher call `saveSelectedFile`, which merges a whole project payload into its Firestore document and then updates Vuex. Sharing regex-checks an email and appends it to the same document. Two snapshot listeners reconcile owner and collaborator queries, processing changes marked as server-originated. This is document synchronization rather than a text merge protocol: concurrent whole-array edits can overwrite one another. A consequential source defect is that saving returns when the previous stored code is empty, so a newly created empty file has no evident path to persist its first edit through this handler. Listener unsubscribe handles are not retained. [ide.vue:626–667](https://github.com/harryt04/minizinc-web/blob/282c9bf2ea853ae0582bb3a78c11180c28700e72/frontend/src/components/ide.vue#L626-L667), [ide.vue:799–817](https://github.com/harryt04/minizinc-web/blob/282c9bf2ea853ae0582bb3a78c11180c28700e72/frontend/src/components/ide.vue#L799-L817), [store.js:123–217](https://github.com/harryt04/minizinc-web/blob/282c9bf2ea853ae0582bb3a78c11180c28700e72/frontend/src/store.js#L123-L217).

**Solve, output, and cancellation.** Solve selects files by name, splits flags on spaces, and posts files, flags, and project ID to a hardcoded HTTPS solver endpoint. Express writes each file under shared `./tmp`, immediately spawns the installed `minizinc` binary, batches console updates into the project's Firestore document, deletes temporary files on close, and returns collected output. The browser also appends the response to its current console and saves it, creating potential duplicated output alongside snapshot updates. Quit targets `/kill-last`, which kills one module-global process, not a per-user job. [ide.vue:819–866](https://github.com/harryt04/minizinc-web/blob/282c9bf2ea853ae0582bb3a78c11180c28700e72/frontend/src/components/ide.vue#L819-L866), [routes/api.js:26–121](https://github.com/harryt04/minizinc-web/blob/282c9bf2ea853ae0582bb3a78c11180c28700e72/routes/api.js#L26-L121).

## Execution and data boundaries

The solver API shows no token verification, ownership check, schema validation, filename confinement, resource limit, or job isolation. It accepts client flags and names directly. `spawn` receives an argument array, so the visible implementation does not concatenate a shell command; nevertheless, unrestricted solver arguments and `./tmp/${file.name}` cross native-process and filesystem boundaries. File writes are asynchronous and not awaited before spawn. Shared filenames can collide, and cancellation can affect another request. Server Admin SDK writes use the supplied project ID without checking membership. These are source risks, not demonstrated exploits. [routes/api.js:27–120](https://github.com/harryt04/minizinc-web/blob/282c9bf2ea853ae0582bb3a78c11180c28700e72/routes/api.js#L27-L120).

Express enables Helmet and unrestricted CORS, serves `server-docs`, and reads TLS material from tracked paths. The tree also contains a service-account JSON path; credential-file contents were deliberately not inspected or reproduced, and validity is unknown. No Firestore security rules are present, so actual database permissions cannot be established. Firebase client configuration is hardcoded; there is no explicit offline setup or conflict recovery in the inspected flows. [server.js:8–38](https://github.com/harryt04/minizinc-web/blob/282c9bf2ea853ae0582bb3a78c11180c28700e72/server.js#L8-L38), [routes/api.js:5–12](https://github.com/harryt04/minizinc-web/blob/282c9bf2ea853ae0582bb3a78c11180c28700e72/routes/api.js#L5-L12).
