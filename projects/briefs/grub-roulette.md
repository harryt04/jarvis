## Purpose and current shape

Grub Roulette helps an individual choose a random nearby, currently open restaurant, then get directions, share its Maps link, inspect photos, or block it. The homepage emphasizes discovering mom-and-pop places, but selection has no independent-ownership/chain filter. It is a small Next.js App Router application with React 18, TypeScript, Tailwind v4 and project-owned shadcn `base-nova` components. There is no account, shared preference database, booking, or ordering flow in the inspected source. [page.tsx:6–32](https://github.com/harryt04/grub-roulette/blob/701e2424ad7467754074f5b556e93f2bd0beb169/src/app/page.tsx#L6-L32), [package.json:17–34](https://github.com/harryt04/grub-roulette/blob/701e2424ad7467754074f5b556e93f2bd0beb169/package.json#L17-L34).

## Location → Google → candidates

`useGeoLocation` requests browser coordinates once and records permission/unavailable/timeout errors. `RestaurantFinder` consumes location/loading, not the error string; its manual location input is always enabled. A trimmed manual value makes search available even while geolocation is pending. The search request omits browser coordinates when manual text is present. Server handling independently gives manual text precedence, geocodes it through Google v4beta, takes the first result, converts the radius from miles/kilometers, then calls legacy Places Nearby Search with `type=restaurant` and custom or default keywords. Both upstream fetches request one-hour Next revalidation. [hook:12–54](https://github.com/harryt04/grub-roulette/blob/701e2424ad7467754074f5b556e93f2bd0beb169/src/app/hooks/useGeoLocation.ts#L12-L54), [finder:83–100](https://github.com/harryt04/grub-roulette/blob/701e2424ad7467754074f5b556e93f2bd0beb169/src/app/components/restaurantFinder.tsx#L83-L100), [route:25–135](https://github.com/harryt04/grub-roulette/blob/701e2424ad7467754074f5b556e93f2bd0beb169/src/app/api/getRestaurants/route.ts#L25-L135).

Validation is lightweight: unknown units return 400; falsy coordinates/radius are rejected, including legitimate zero coordinates. Radius lacks positive/range checks, and JSON parsing is outside the route's catches. No pagination follows Google's next-page token. The client propagates restaurant errors into a visible alert; detail/photo failures instead become `null`, allowing a basic result without enrichment. [route:5–89](https://github.com/harryt04/grub-roulette/blob/701e2424ad7467754074f5b556e93f2bd0beb169/src/app/api/getRestaurants/route.ts#L5-L89), [client-utils/getRestaurants.ts:3–68](https://github.com/harryt04/grub-roulette/blob/701e2424ad7467754074f5b556e93f2bd0beb169/src/app/client-utils/getRestaurants.ts#L3-L68).

## Selection, persistence, and reset

The actual state owner is `restaurantFinder.tsx`: React state holds form/result/blacklist/loading, while module-scope `placesMap`, `usedPlaces`, and `placeDetailsCache` survive component rerenders. On an empty candidate map it fetches restaurants, retains only `open_now` plus `OPERATIONAL`, deduplicates by **name**, then randomly selects an unused candidate outside the blacklist. Used identities are names; blacklist matches either name or place ID. Same-name branches therefore collapse. Pure helpers in `src/lib/restaurant-logic.ts` duplicate filtering/selection but are not imported by the finder; helper tests alone cannot guarantee UI behavior. [finder:37–150](https://github.com/harryt04/grub-roulette/blob/701e2424ad7467754074f5b556e93f2bd0beb169/src/app/components/restaurantFinder.tsx#L37-L150), [restaurant-logic.ts:13–44](https://github.com/harryt04/grub-roulette/blob/701e2424ad7467754074f5b556e93f2bd0beb169/src/lib/restaurant-logic.ts#L13-L44).

Changing radius, keywords, coordinates, or manual text clears candidates/used names, but leaves the displayed result, blacklist and detail cache. Blocking persists `{place_id,name}` to `grubroulette_blacklist` and requests another draw. Resetting blocked places empties that storage and candidates/used names, then refetches; it does not clear detail cache. Exhaustion displays a sentinel message and clears candidates, so a subsequent draw begins a new cycle. There is no request cancellation or generation check when criteria change during an await. [finder:61–237](https://github.com/harryt04/grub-roulette/blob/701e2424ad7467754074f5b556e93f2bd0beb169/src/app/components/restaurantFinder.tsx#L61-L237).

Details cache persists as a whole-map snapshot with one timestamp. Expiry is checked only on mount/load, and each save refreshes the snapshot timestamp, including older entries. Blacklist persists without expiry. Reads recover from malformed JSON, but writes and some storage access can throw. These are browser-local preferences, not offline search; Google requests remain necessary. [localStorage.ts:3–48](https://github.com/harryt04/grub-roulette/blob/701e2424ad7467754074f5b556e93f2bd0beb169/src/lib/localStorage.ts#L3-L48).

## Details, photos, and boundaries

An uncached selection POSTs its ID to `/api/getPlaceDetails`, which returns legacy Google `data.result`; photo references then POST as `{photos:[...]}` to `/api/getPhotos`. The finder merges address, description, closing text, Maps URL, phone, price and website into the result. Photos are fetched again for each enriched selection rather than included in the details cache. `PlaceDetails` provides clipboard sharing, a Safari-specific directions preference, masonry images, and a custom portal viewer with Escape/close, tap/wheel zoom, pan and pinch; it resets zoom/pan on opening. [finder:144–183](https://github.com/harryt04/grub-roulette/blob/701e2424ad7467754074f5b556e93f2bd0beb169/src/app/components/restaurantFinder.tsx#L144-L183), [placeDetails.tsx:26–142](https://github.com/harryt04/grub-roulette/blob/701e2424ad7467754074f5b556e93f2bd0beb169/src/app/components/placeDetails.tsx#L26-L142), [modal.tsx:58–305](https://github.com/harryt04/grub-roulette/blob/701e2424ad7467754074f5b556e93f2bd0beb169/src/app/components/modal.tsx#L58-L305).

**Consequential policy conflict:** environment guidance says the Google key must never reach the client, while the photo route returns URLs containing that key; images are unoptimized browser requests. These are ordinary API-key URLs, despite AGENTS calling them “signed.” A unit test explicitly expects key inclusion. No route authentication or rate limiting is implemented here; deployed restrictions are unknown. [environment example:1–3](https://github.com/harryt04/grub-roulette/blob/701e2424ad7467754074f5b556e93f2bd0beb169/.env.local.example#L1-L3), [photo route:4–19](https://github.com/harryt04/grub-roulette/blob/701e2424ad7467754074f5b556e93f2bd0beb169/src/app/api/getPhotos/route.ts#L4-L19), [google-maps.ts:5–7](https://github.com/harryt04/grub-roulette/blob/701e2424ad7467754074f5b556e93f2bd0beb169/src/lib/google-maps.ts#L5-L7), [photo test:74–78](https://github.com/harryt04/grub-roulette/blob/701e2424ad7467754074f5b556e93f2bd0beb169/src/__tests__/api/getPhotos.test.ts#L74-L78).

## UI decisions and historical limits

Standing guidance explicitly says **no Zustand**: the old `.agents/specs/rewrite/` store was planned, not implemented; those specs are absent from this checkout. Base UI triggers use `render={<Button/>}`, not Radix `asChild`. Theme preferences are separate: next-themes owns the HTML class and defaults to system; palette context validates/persists five palettes and chooses randomly on first visit, using `data-palette`. Palette styles are intentionally injected in layout to avoid Tailwind purging. These are project decisions, not global Harry preferences. Harry's recent commits include manual overrides (`33ecfd5`), theme preferences (`d3b391e`, `f626139`), and constrained tagline layout (HEAD).
